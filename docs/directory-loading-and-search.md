# 目录加载与搜索设计

## 目标

打开文件夹是文件管理器的主流程，不能被搜索索引、内容解析或后台扫描阻塞。目录很大、位于外接磁盘或网络磁盘时，也必须先保证浏览可用。

## 职责划分

| 场景 | 数据来源 | 是否在打开文件夹时运行 |
| --- | --- | --- |
| 显示当前文件夹 | 直接读取当前目录 | 是，只读取当前层 |
| 按文件名搜索（macOS） | Spotlight（聚焦搜索，Finder 使用的系统元数据索引） | 否，搜索时查询系统索引 |
| 按文件名搜索（其他系统或 Spotlight 启动失败） | 有上限的文件系统扫描 | 否，搜索时运行 |
| 文件内容、自然语言及 AI 搜索 | Wisp 内容索引 | 否，由用户明确选择目录后建立 |
| 当前目录变化刷新 | 文件系统监听器 | 是，只监听当前层 |

## 当前实现约束

1. 普通目录导航只更新搜索上下文，不再自动读取文件内容或启动索引。
2. “自动加入访问过的文件夹”默认关闭。用户主动开启后，访问目录才会加入 Wisp 内容索引。
3. macOS 文件名搜索通过 `/usr/bin/mdfind` 查询 Spotlight，并限制最多返回 1000 个文件或文件夹。
4. Spotlight 无法启动时使用限量文件系统扫描。隐藏目录和外接盘可能未被 Spotlight 收录，因此这两类位置在系统索引返回空时也会限量扫描。扫描最多检查 50000 个目录项、返回 1000 个文件或文件夹，并跳过内部隐藏目录、`.git`、`node_modules`、`target`、`build` 等高噪声目录。
5. 两个分栏打开同一路径时，共享同一份目录读取结果；短时间返回刚访问的目录时使用 5 秒缓存。文件操作、刷新和文件系统事件仍会立即重新读取。
6. 应用启动时只加载已经保存的 Wisp 内容索引，不遍历白名单做完整校验。内容索引缺失或需要更新时，由用户在内容搜索设置中明确执行重建。

## 为什么不完全删除 Wisp 索引

Spotlight 很适合文件名和系统元数据搜索，但不能替代 Wisp 对文件内容、自然语言和 AI 信息的专用索引，也不是跨平台方案。因此采用“双层搜索”：系统索引负责快速找名字，Wisp 索引只负责用户明确需要的深度搜索。

## 已知边界与下一步

- Spotlight 被系统隐私设置排除的普通目录仍可能没有文件名搜索结果；Wisp 不会因为任意空结果就扫描整块磁盘。隐藏目录和外接盘会使用最多 50000 项的限量补救。
- 当前目录读取仍会一次返回当前层的全部项目。若真实测试中单层目录达到数万项、网络盘首屏仍慢，下一步应新增分页/渐进加载：先返回首批项目，再补充剩余项目和 Finder 替身信息。该改动涉及排序、选择和拖拽的一致性，需要单独设计与测试，不在本次保守修改中直接加入。
